# 降低 Prefill forward 耗时估计误差的方法

更新：2026-09-16。本文整理 Kimi-K3 实验中讨论的改进方法及其验证依据。目标是提高“用同构测点估计实际 batch 耗时”的准确性；本文不代表已经修改默认定价算法。

建议按以下顺序推进：**先减少网格取点造成的工作量失配，再处理长度不均衡和 DCP context 分块差异，最后用独立的真实形状回放验证累计耗时。** Query 网格缩到 256 已有局部实测支持；保留工作量的插值、按 b 分格、分块成本修正和长尾单独定价仍需验证。

## 1. 已有证据与适用范围

早期 [GPU-event 误差评估](../experiments/exp1_kimi_k3/Forward_error_evaluation.md)在后来 C=32 测试的异构命中子集上得到 MAPE 21.63%。它包含网格、跨轮测量和共享前缀差异，不是原 CI 全段误差。

后续 [30 对 Prefill 原始形状回放](../experiments/exp1_kimi_k3/forward_wall30/run02/Report.md)保留原始整数 `ctx[]/q[]` 和顺序，双方使用独立 KV，在同一轮测量模型完成 wall time。30 对的 MAPE 为 **12.95%**；其中 15 对多请求 batch 为 **24.94%**。这验证了当前最终同构测点对一部分多请求 batch 存在明显低估。

[Query 网格细化实验](../experiments/exp1_kimi_k3/prefill_qgrid_wall/run01/Report.md)在同一轮重新测量原始 batch、1024 基线和细网格点。三个网格共同可测的 **27 个 batch** 结果如下：

| Query 跨度 | MAPE | P95 绝对相对误差 | 累计耗时偏差 |
|---|---:|---:|---:|
| 1024 | 8.48% | 35.32% | −11.64% |
| 256 | 4.05% | 14.33% | −4.42% |
| 128 | 3.92% | 16.04% | −4.47% |

计时边界为 CPU 时钟包围 `ModelRunner.run_model` 和设备完成同步，取 8 个 rank 的最大 wall time；包含 logits、CPU dispatch、GPU 执行和 TP/DCP 通信，输入及 KV/state 准备、恢复、采样、调度和网络在计时外。它与早期 GPU event 指标不同，不能混用数值。

27 个共同样本不包含 P24/P29/P30。包含 P29/P30 的 **29 个 1024/256 配对样本**中，MAPE 为 **12.10% → 7.47%**，最大误差仍为 **66.81%**。这些都是分层选取的固定形状样本；合成 token 没有恢复原请求内容或 MoE 路由，也不是全 trace 的无偏误差估计。

## 2. 减少网格取点造成的工作量失配

### 2.1 先用 256 query 跨度作为细化候选

保持 context 跨度 8192、`no_snap_below=1024` 和其它配置一致，将 query 跨度从 1024 改为 256。已有共同样本上的 MAPE 降低 4.43 个百分点；128 相比 256 只再降低 0.13 个百分点，P95 反而上升。因此优先验证 256 的测点数量、可测覆盖率和误差，再决定是否局部细化到 128。

需要同时检查两个副作用：

- 重新划分 query 格子会改变格内 context 中位数，所以最终 c 也可能变化。P18 的 context 分块数从原始 13，变成 1024 网格的 2、细网格的 1；误差从 −18.78% 变为 −22.95%。不能假设所有点都随网格细化而改善。
- 细网格仍可能产生超过 8192-token 预算的点：P24 的 256 点为 8448 token，P29/P30 的 128 点分别为 8320/8448。应另选合法点或标记缺失，不能截断 query 后仍称为原测点，也不能通过增大引擎预算混入另一种配置。

现有 [gen_final_points.py](../scripts/gen_final_points.py) 在未指定时会让 `no_snap_below` 跟随 `q-bin`。复现本次细化实验必须显式固定为 1024；候选生成及上机命令见[网格实验说明](../experiments/exp1_kimi_k3/prefill_qgrid_wall/README.md)。

### 2.2 查表时保留原始 Q，避免用格子中位数直接替代每个 batch

对实际 batch 保留：

```text
b = 请求数
Q = Σ q_i
A = Σ [q_i*c_i + q_i*(q_i+1)/2]
q_eq = Q/b
c_eq = A/Q − (q_eq+1)/2
```

[工作量等价法](ragged_packed_prefill_workload_equivalence.md)在这一中间点精确匹配 Q 和 causal attention pairs。误差可能在后续换成格子代表点时被放大：当前 cell key 只有 `(c_bin,q_bin)`，不含 b，格内多种 b 共用中位数。P27 的原始 `Q=8174,b=4,q_eq=2043.5`，最后却取 `q=1024`，价格点 Q 降到 4096。

后续改进应优先验证：

1. **按原始 `(c_eq,q_eq,b)` 查询时间。** 同 b 下有局部合法测点包围查询位置时，插值耗时；缺少包围点时补测或显式标记外推。若输入表是吞吐，先用 `t=b*q/TPS` 转为时间。
2. **减少跨 b 的代表点污染。** 以 `(b,c_bin,q_bin)` 分格或按 b 分层选点，检查覆盖率和测点数的代价。它不能自动保证每个 batch 的 Q 被保留，还需逐 batch 核对。
3. **保存映射失配。** 对每个 batch 输出 `Q_point/Q−1`、`A_point/A−1`、实际和最终坐标；明显失配的点进入补测集合。工作量偏差是诊断量，不能直接当成时间误差。

若 Q 不能被 b 整除，整数长度的完全同构 batch 无法精确保持 Q。可以在合法测点间插值，或直接测原始形状；使用向下/向上取整的近同构向量时，必须记录它仍是另一种形状及其工作量残差。不要把旧时间直接乘 `Q/Q_point` 视为已经校准：固定开销、attention、通信和分块成本不都随 Q 线性变化。

这些保留工作量的查表改进尚未由当前网格实验单独验证。网格实验只改变了跨度，并未实现插值或按 b 分格。

## 3. 对长度不均衡和 DCP context 分块单独建模

Q 和 A 接近不意味着时间接近。P18 的 1024 点 Q 只比原始多 1.16%，仍低估约 19%；P30 在 256 网格下 Q 偏差缩到 −5.50%，耗时仍低估 **66.81%**。

当前 K3 的 DCP Prefill 按每条请求的 cached context 分块。TP8/DCP8、block size=128、context chunk budget=16384 时，令 `n_ctx = count(c_i>0)`：

```text
n_ctx == 0 时没有 cached-context 分块；否则：
local_chunk_size = max(128, floor(floor(16384/(n_ctx*8))/128)*128)
max_padded_local = max_i(ceil(c_i/1024)*128)
num_chunks = ceil(max_padded_local/local_chunk_size)
```

P30 的原始 `num_chunks=335`，1024 和 256 同构点均为 60。每轮会执行 KV gather、AllGather、重排、解压、attention 和合并，平均 context 长度不能表达这部分循环次数。实现和日志依据见 [wall-time 报告的 P30 分析](../experiments/exp1_kimi_k3/forward_wall30/run02/Report.md)；实验中的计算见 [analyze_grid.py](../experiments/exp1_kimi_k3/prefill_qgrid_wall/analyze_grid.py)。上述常数只适用于这套实现和配置。

后续定价应保留原始长度向量，并把以下量用于分层选点、局部修正或长尾判别：`n_ctx`、`max(c_i)`、`num_chunks`、query 不均衡度 `max(q_i)/q_eq`，以及原始/测点分块数差异。先验证分块明显不匹配的样本，再判断是否需要更细的逐块工作量模型。

这是已有实现证据支持的改进方向，尚没有测得通用修正系数。不能把整个 forward 时间按 `num_chunks` 比例放大，也不能直接用最大 context 替代 `c_eq` 后声称得到严格上界；两者都会改变其它成本。应通过独立验证判断修正的收益。

## 4. 长尾补测与真实形状定价

优先补测高频、fresh token 占比高、工作量失配大或分块失配大的多请求 batch；保留短尾块、长短 query 混合和不同 b 的覆盖。对 P29/P30 一类长尾，可以直接测原始形状并保存专用价格，待验证模型能覆盖后再减少直接测点。

[forward_wall30](../experiments/exp1_kimi_k3/forward_wall30/README.md) 已提供原始形状回放方式：各请求独立 KV、精确 context 处的 KDA 状态、每次计时前恢复，原始长度和顺序不缩放。它验证了测量方法可用；把原始形状价格加入全段估计仍是待完成的定价工作。复用价格时还需核对模型版本、硬件、TP/DCP、KV dtype、执行路径和计时边界。

同构或异构测量都应检查实际 `(ctx[],q[])`，不以客户端并发数代替实际 batch size。Serving harness 还受 checkpoint/hash block 约束：`q≥1024` 且未对齐的目标可能被拆步；256/128 网格实验通过直接构造输入及 KV/state 测得的单次调用，不意味着旧 HTTP harness 能原样构造这些点。详见[测点方法](measure_prefill_performance_point.md)。

## 5. 如何验证改进确实降低了误差

固定同一批原始 batch、同一轮环境及计时边界，尽量设置三个对照：原始异构形状、未经过粗网格的同构等价点、最终网格测点。中间点不可执行时应记录原因，不能把最终替代误差全部归于同构化或网格。

每个形状充分预热，交替或轮换测量，分别保留重复样本。两侧都恢复相同 context 状态并使用独立 KV。先检查长度、token 数、样本数和计时边界，再比较结果；GPU event、同步模型完成 wall time、TTFT 和 step period 分别报告。

至少报告：

- 单请求、多请求以及 b/context/分块分层的 MAPE、P95 和最大绝对相对误差。
- 同一覆盖子集的累计耗时偏差 `ΣT_est/ΣT_real−1`，以及固定原始 token 分子的吞吐偏差 `ΣT_real/ΣT_est−1`。
- forward、fresh token 和测点覆盖率；不可测点、补值点及外推点的数量和占比。
- 各方法共同可测集合和包含长尾的成对集合，避免只因困难样本退出集合而显得误差改善。

新修正应在选点/拟合未使用的形状上验证。同一个测点的多次调用只衡量重复计时波动，不能代替独立形状验证；按 key 频次加权的代表样本结果也不能自动推广到该 key 的全部实际 batch。

## 6. 当前状态与后续顺序

| 方法 | 当前证据或状态 | 后续动作 |
|---|---|---|
| Query 跨度 1024 → 256 | 已完成 30 个原始形状的网格实验；1024/256 可配对 29 个，共同可测集 MAPE 改善 | 扩大验证集，处理不可测点，核对新点表覆盖率 |
| 同 b 下保留 Q/A 的查询、插值或补测 | 严格等价公式已有；当前默认最终点仍按格子代表值定价 | 比较逐 batch 查询与按 b 分格的收益和测量成本 |
| DCP 分块及不均衡特征修正 | P18/P30 与实现代码支持；无已验证系数 | 对分块差异大的样本成对测量并独立验证 |
| 长尾原始形状直接定价 | 回放测量工具已有 | 补足长尾，明确直接价格能覆盖的实际形状 |

落实时先冻结原 trace、测点表和脚本版本，在独立目录生成新坐标与误差结果。历史 `(final_c,final_q,b)` 变化后，旧价格只能按完整坐标和配置核对复用；不能按相同 priority 连接。默认估计器是否切换，应以新增验证和全段覆盖率结果为依据。
