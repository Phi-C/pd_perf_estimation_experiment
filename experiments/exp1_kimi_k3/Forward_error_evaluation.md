# Kimi-K3：同构 batch 定价的 forward 耗时误差

评估日期：2026-09-14。分析沿用已有测量，没有新增 GPU 实验，也没有拟合误差修正系数。

后续进展：已另行完成[原始形状与最终测点的同步 wall-time 对照](forward_wall30/run02/Report.md)和[query 网格细化实验](prefill_qgrid_wall/run01/Report.md)。降低 Prefill 估计误差的方法、已验证收益和剩余长尾问题整理在[方法说明](../../prefill/forward_estimation_accuracy.md)。下文保留早期 GPU-event 评估口径，不与后续 wall-time 数值混用。

**Decode 有成对验证：用同构 batch 的 GPU 耗时中位数预测真实长度分布回放的每一步，MAPE 为 2.22%，P95 为 4.95%；若比较每组的耗时中位数，MAPE 为 0.90%。Prefill 尚不能确定原 CI trace 的耗时误差，但在独立的 C=32 补充测试中，历史定价流程对可命中的异构 batch 的 MAPE 为 21.63%，累计耗时低估 21.90%。后者包含网格取点和跨轮测量的影响，不能当作严格工作量等价映射的独立误差。**

## 1. 评估对象与口径

需要区分三层：实际异构 batch → 严格工作量等价点 → 网格代表测点 → 测得的时间。网格量化、测量波动和未命中补值都可能另外带来误差。

本报告的真值均取探针的 `fwd_gpu_ms`（GPU event 包围 `run_model`）；不用客户端 TTFT、秒级 trace slice 或引擎 CPU 调用耗时替代 GPU 真值。

对第 f 个样本，定义：

```text
e_f = (预测耗时 / 实测耗时 − 1) × 100%
MAPE = mean(|e_f|)
累计耗时偏差 = (Σ预测耗时 / Σ实测耗时 − 1) × 100%
吞吐偏差 = (Σ实测耗时 / Σ预测耗时 − 1) × 100%  # token 分子保持一致
```

负的耗时偏差表示低估耗时，对应高估吞吐。P95 是绝对相对误差的经验 95 分位，使用 NumPy 的线性分位数；不是置信上界。逐步误差包含步间波动；逐组中位数误差衡量代表耗时的偏差。累计指标只针对表内同一验证子集。

## 2. Decode：成对验证与历史主表验证

### 数据与恢复检查

使用 `decode/bench_run/traces_calib_results.csv` 中最后一次记录的 64 个 OK 结果：16 个等价点，每点 A/B/C/D 四种形状。

- A：同构长度基准。
- B：从原 trace 取长度向量，将均值归一到 `L_test` 并按 1024 token 对齐后的回放。保留了原分布的主要不均衡特征，但不是逐 token 原样重放。
- C/D：一长多短、两长多短的构造对照。

从 `decode/bench_run/fwdprobe_decode.jsonl` 恢复全部 64 个采样窗口。按保存的首步平均/最小/最大长度、末步平均长度、样本数匹配，再同时核对 GPU 时间的中位数及均值，容差为原表的 0.001 ms 舍入精度。全部窗口唯一匹配、互不重叠；保留原测量已丢弃 20 步暖机后的样本，没有额外按延迟剔除异常值。

16 个 B 窗口共 **4,475 步**；B/C/D 合计 **13,435 步**。每窗 277–280 步。b=13–33，目标平均长度 73,728–221,184，B 的 `CV_L=0.3219–1.0101`，`r_max=1.5277–4.7289`。

### 每次 forward 的误差：主要结果

用各点 A 的 GPU 耗时中位数预测其 B/C/D 窗口中的每一次 forward，不做异构修正：

| 预测表 / 验证样本 | forward 数 | MAPE | P95 | 最大绝对相对误差 | 累计耗时偏差 |
|---|---:|---:|---:|---:|---:|
| 同点 A → B 真实分布回放 | 4,475 | **2.22%** | **4.95%** | 16.03% | −0.0012% |
| 同点 A → B/C/D 全部对照 | 13,435 | 2.18% | 5.14% | 17.84% | +0.1154% |
| 历史主表 → B 真实分布回放 | 4,475 | **2.31%** | **5.22%** | 15.16% | +0.0306% |
| 历史主表 → B/C/D 全部对照 | 13,435 | 2.19% | 4.86% | 15.99% | +0.1471% |

第一行平均绝对误差为 **0.678 ms**。B 的实测 GPU 时间累计 **138.4668 s**，同点 A 预测 **138.4651 s**，历史主表预测 **138.5092 s**。累计误差很小来自这个验证集合中正负偏差的抵消，不能视为原 113,439 步全段误差的保证。

历史主表按 `(L_test,b)` 连接 `traces_top150_results.csv`，沿用现有定价流程的最后一条 OK 结果和 `fwd_gpu_ms_p50`。它是另一次同构测量，可以检查复用点表的实际偏差。

### 每组代表耗时的误差

将每个验证窗口先取 GPU 时间中位数，再与同构价格比较：

| 预测表 / 验证样本 | 组数 | MAPE | P95 | 最大误差 | 代表耗时之和偏差 |
|---|---:|---:|---:|---:|---:|
| 同点 A → B | 16 | **0.90%** | **2.28%** | 2.37% | −0.43% |
| 同点 A → B/C/D | 48 | 0.97% | 2.44% | 2.93% | −0.19% |
| 历史主表 → B | 16 | **1.26%** | **3.08%** | 3.36% | −0.40% |
| 历史主表 → 新测 A，同构重复测量对照 | 16 | 1.03% | 2.09% | 2.36% | +0.03% |

这说明本组数据中异构映射没有引入明显的大幅偏差，组间偏差与不同轮次同构测量的差异在相近量级。旧报告的约 0.96% 是修正模型的样本内拟合误差；这里的 **0.97% 是完全不拟合修正的 48 组 GPU 中位数预测误差**，两者含义不同。

换用每组 GPU **均值**时，同点 A → B 的 MAPE 为 **0.86%**，P95 为 **1.55%**，代表耗时之和偏差为 **−0.34%**。引擎 `D_ms` 中位数口径的对应 MAPE 为 **0.91%**、P95 为 **2.25%**；它们均未与 GPU 口径混合。

### 覆盖范围

这 16 个 `(L_test,b)` 在原 profiling trace 中对应 **13,131/113,439 个 forward（11.58%）**、**297,753/2,247,264 个 output token（13.25%）**。每个键只验证一个 B 长度分布，不能把“键覆盖”当作覆盖了其全部异构形状。

若仅在这 16 个键上按原 forward 次数加权，历史主表 → B 的组中位数 MAPE 为 **1.40%**，代表耗时累计偏差 **−0.31%**。这依然是已覆盖键的回放结果，不是原始运行逐步真值的对账。

未独立验证：原 trace 中其它长度分布、长度分桶偏移，以及未命中主表时使用的 `ceil(b/16)` 波均值补值。特别是 b=34–37 的外推不在这些成对样本内。

## 3. Prefill：原 trace 的缺口与可执行的补充验证

### 已恢复 GPU 点表，但仍缺原 CI 的逐步真值

此前报告认为缺失的文件实际保存在：

```text
/it-share/xingjche/atom_instr/RESULTS_probe_vs_bench.csv
/it-share/xingjche/atom_instr/fwdprobe.jsonl
```

本次将点表原样恢复到 `bench_run/RESULTS_probe_vs_bench.csv`。使用当前 `scripts/join_prefill_probe.py` 从历史原始探针重新生成，和恢复的 CSV **逐字节一致**。共有 **210 个有效同构价格点**。

原 profiling trace 的 **4,305 个 forward** 中，3,578 个为 b=1（83.11%），727 个为多请求 batch（16.89%，占 23.38% fresh token）。b=1 的严格异构转同构映射是恒等变换，但网格取点和时间表复用仍可能有误差。

恢复后的点表命中 **3,400 个 forward**，其中只有 **269/727 个多请求 forward（37.00%）**。这 3,400 个 forward 的预测总 GPU 时间是 **1,034.7704 s**；可复现旧报告的 10,066 fresh tok/s / 204,801 ISL tok/s。它们是用同构表回代得到的估计，不是原 CI 的 GPU 测量。

原 CI 日志的 scheduler 时间只有秒级精度；Perfetto 中的 forward slice 经过同秒平铺和等待估算。**不能拿这些 slice 计算 GPU 耗时 MAPE**。因此当前还不能报出原 CI 4,305 个 Prefill forward 的真实累计误差。

### 补充测试：冻结历史定价流程，预测后来的实际 C=32 batch

使用后来 α=0.8 Prefill C=32 实验的 109 个成功测量窗口。窗口字节边界来自 `stat_alpha0.8/measure/prefill/c32.csv`；实际 GPU 探针在 **`stat_alpha0.8/measure/decode/fwdprobe_decode.jsonl`**，虽然路径叫 decode，其中也包含此次 Prefill 测量。

测试流程：

1. 仅保留非 dummy 的纯 Prefill，读取每个 forward 的真实 `q[]`、`ctx[]`、GPU 时间；包括测量窗口内的暖机和尾块，不按时长筛选。
2. 按严格公式计算 `q_eq=Σq/b`、`c_eq=Σ[q*c+q(q+1)/2]/Σq−(q_eq+1)/2`。
3. 冻结原完整 trace 的 8192×1024 格子及已保存 `final_c/final_q`；使用同一 `(final_c,final_q,b)` 连接历史 GPU 点表。没有价格的样本保持未命中，不做补值。
4. 将预测时间与本次 forward 的 GPU 时间比较。历史表只由同构样本生成，验证用的异构样本没有参与定价。

共找到 5,315 个纯 Prefill forward，其中 4,543 个异构 batch。可定价的异构子集有 **1,260 个**，来自 **37 个测量窗口**，覆盖异构 forward 的 **27.73%**、异构 fresh token 的 **28.23%**。

| 验证子集 | 命中 forward 数 | MAPE | P95 | 最大误差 | 累计耗时偏差 | 同分子吞吐偏差 |
|---|---:|---:|---:|---:|---:|---:|
| b=1 对照 | 620 | 3.47% | 10.76% | 17.43% | −2.71% | +2.78% |
| 多请求同构对照，样本很少 | 9 | 2.74% | 5.41% | 5.93% | −1.15% | +1.16% |
| **异构 batch** | **1,260** | **21.63%** | **25.14%** | **39.44%** | **−21.90%** | **+28.03%** |

异构子集预测 **551.118 s**，实测 **705.616 s**；分子均为这批 batch 的 **10,126,147 fresh token**。这些数不是整个 C=32 工作负载的吞吐，也不能乘到原 CI 吞吐上作修正。

样本按 b 分布为：b=2 有 86 个，b=3 有 1,134 个，b=4 有 12 个，b=5 有 4 个，b=6 有 24 个。b=3 占命中样本的 90%，因此不能将 21.63% 视作各类 batch 都相同的误差。把 37 个窗口各自的 MAPE 等权平均，结果为 **17.66%**。每窗口再去掉首尾各 8 个纯 Prefill 样本，剩余异构命中 1,161 个，MAPE 为 **21.80%**、累计偏差为 **−22.00%**，没有因去掉边界而消失。

### 已确认的失配：网格代表点没有保住实际 token 工作量

1,134 个 b=3 样本实际每步有 **8,065–8,192 token**，多数为 8,066–8,068；`q_eq` 约为 2,689，却被原网格映射到 `q=2048,b=3`，价格点只有 **6,144 token**。其新 token 工作量少约 24%–25%，该组实测耗时低估 **22.12%**。

一个可直接核对的例子（窗口 priority=26，probe seq=474043）：

| 项目 | 值 |
|---|---|
| 实际 q | `[3, 128, 7936]` |
| 实际 ctx | `[43008, 42880, 34816]` |
| 严格等价点 | `b=3, q_eq=2689, c_eq=37507.08` |
| 网格价格点 | `b=3, q=2048, c=40960` |
| Query 工作量偏差 / attention pair 偏差 | **−23.84% / −17.70%** |
| 预测 / 实测 GPU 时间 | **367.30 / 471.24 ms** |
| 耗时误差 | **−22.06%** |

严格公式在映射到 `(2689,37507.08,3)` 时保持了 token 数和 attention pair 数；后续换成 `(2048,40960,3)` 才改变工作量。这是当前实现中的可观测失配。由于缺少严格等价点的成对测量，**不能把全部 22.06% 都归因于网格，也不能据此认定严格等价公式本身有 22% 误差**。

原 CI 多请求 batch 在网格取点后的新 token 工作量绝对相对偏差中位数为 **24.15%**，P95 为 **51.60%**。这些是工作量差异，不是运行时间误差，但说明该问题也存在于原 trace 的映射中。对很短的尾块，相对工作量偏差可以非常大，不能线性转成耗时偏差。

### 补充测试不能回答的部分

- C=32 实验各请求共享 cached prefix，原 trace 请求拥有独立 KV；缓存状态、测量日期和 batch 分布均有差别。
- 冻结网格在原 trace 上选取，C=32 是另一个分布；误差说明这套表直接复用时存在风险，不能替代原分布上的验证。
- 1,260 个异构命中样本中，没有同时满足 query 与 attention 工作量各相差 ≤1% 的价格匹配。因此该子集不能隔离“严格等价点上的同构替代”误差。
- 没有覆盖的 72.27% 异构 forward 不被算入 21.63%；不能默认它们具有相同误差。

## 4. 对当前吞吐估计的含义

**Decode**：在已测范围内，同构基线可作为较准确的 forward 价格。逐步误差约 2%–3%，P95 约 5%；代表耗时误差约 1%。现有证据不支持为了拟合这组数据而增加复杂异构修正。仍需另验分桶、补值以及未覆盖的 b/长度范围。

**Prefill**：目前不宜给原 trace 的估计附上“误差只有几个百分点”的结论。已证实历史网格会明显改变工作量；补充测试中异构命中子集的吞吐高估约 28%。下一步应优先保留 `Q`，在同 b 下按时间插值或直接补测接近实际 `q_eq` 的点，再用原 trace 多请求 batch 及其同构等价点做同环境、独立 KV 的成对回放。测点选择应同时考虑频率、fresh token 和未覆盖的大 batch，保留独立验证点。
